# Как вести разработку

Приложение — нативный тренажёр печати для macOS (Swift 6.2, SwiftUI, SwiftData). Правила короткие, но обязательные.

## Ветки и pull request

- Работа идёт в отдельной ветке: по фазе (`phase3-streak-analytics`) или по фиче/исправлению (`fix/...`, `feature/...`).
- В `main` попадает только через pull request. Прямых коммитов в `main` нет.
- Перед PR должны проходить `swift test` и сборка без предупреждений; то же проверяет CI (`.github/workflows/tests.yml`).

## Тесты

- Каждая задача идёт с тестами: сначала тест и красный результат, потом код и зелёный результат.
- Чистая логика живёт в `TypingCore` (без AppKit, SwiftUI, Carbon, AVFoundation), тесты — Swift Testing.
- Тесты, которые вызывают Carbon TIS, помечаются `@MainActor`.
- Все новые строки интерфейса добавляются в `Localization/{ru,en}.lproj/Localizable.strings` (для ядра — в `Sources/TypingCore/Resources/{ru,en}.lproj`); тест-сторож проверяет перевод. Язык исходных строк — русский.

## Коммиты

- Тема коммита на русском, коротко и по делу.
- Один коммит — одна законченная мысль вместе с тестами.

## Версии и CHANGELOG

- Версия — [семантическая](https://semver.org/lang/ru/), живёт в файле `VERSION`. Во время работы над версией там `X.Y.Z-dev`.
- Соответствие фазам: 0.1.0 — фаза 1 и 1.1, 0.2.0 — фаза 2, 0.3.0 — фаза 3, 1.0.0 — после фазы 4, 1.1.0 — фаза 5, 1.2.0 — фаза 6a, 2.0.0 — фаза 6b, 2.1.0 — фаза 6c, 2.2.0 — фаза 6d, 2.3.0 — фаза 6e, 2.3.1 — фаза 7a, 2.4.0 — фаза 7b. Исправления между фазами — патч-версии.
- Всё заметное для пользователя сразу записывается в `CHANGELOG.md` в раздел `[Unreleased]` (Добавлено, Изменено, Исправлено).
- Выпуск версии (релиз собирает CI по тегу, `.github/workflows/release.yml`):
  1. В `VERSION` убрать `-dev`; в `CHANGELOG.md` переименовать `[Unreleased]` в `[X.Y.Z] - дата`, вернуть пустой `[Unreleased]` и обновить ссылки сравнения внизу.
  2. Скопировать раздел в `docs/releases/vX.Y.Z.md` (это текст релиза на GitHub); обновить значок версии в `README.md` и `README.en.md`.
  3. Слить PR в `main` и поставить аннотированный тег: `git tag -a vX.Y.Z -m "Версия X.Y.Z" <merge-коммит>`, затем `git push origin vX.Y.Z`.
  4. Workflow `release` проверяет, что тег равен `v` + `VERSION`, версия без `-` и есть `docs/releases/vX.Y.Z.md`; затем собирает и тестирует проект и создаёт **черновик** релиза с файлами `TenFingers-X.Y.Z.dmg`, `TenFingers-X.Y.Z.zip`, `release.json` и `SHA256SUMS`. Если что-то не так, он падает до сборки с понятным сообщением.
  5. Открыть черновик в GitHub → Releases, проверить файлы и текст, нажать «Опубликовать». Обновление в приложении увидит только опубликованный релиз. Если релиз с этим тегом уже есть, повторный запуск workflow перезаписывает файлы и не трогает текст.
  6. В `VERSION` поставить следующую `-dev`-версию.
- Скрипты релиза (`make-bundle.sh`, `package-release.sh`, `update-relaunch.sh`, `*.entitlements`) и сам workflow проверяются без тега: при их изменении в PR, а также вручную (Actions → release → Run workflow) workflow идёт в режиме dry run — всё то же без `gh release`, файлы лежат в artifacts запуска.
- Версия, номер сборки (число коммитов) и короткий хэш подставляются в `Info.plist` собранного приложения (`scripts/make-bundle.sh`, см. «Сборка бандла»); они видны в «О программе» и внизу настроек.

## Сохранность данных

Пользователь уже занимается в приложении, его прогресс терять нельзя (спецификация, раздел 20).

- Схема меняется только аддитивно: новые модели без ограничений, новые поля существующих моделей — только со значениями по умолчанию. Никаких переименований и удалений полей.
- Первым в каждой фазе, где меняется схема, идёт маркер поколения схемы; приложение отказывается открывать базу более нового поколения.
- Папку `~/Library/Application Support/TenFingers` вне приложения не трогать. Для проб — копии в `/private/tmp`.

## Сборка и установка

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
swift test
./scripts/build-app.sh
```

Скрипт собирает релизную версию, подставляет версию в `Info.plist`, подписывает ad-hoc, делает резервную копию прогресса (`~/Library/Application Support/TenFingers.backups`) и устанавливает приложение как `/Applications/TenFingers.app` (в Finder оно называется «Десять пальцев» на русской системе и «TenFingers» на английской; старый бандл «Десять пальцев.app» удаляется). Язык интерфейса выбирается в «Настройки → Общие».

### Сборка бандла

`scripts/make-bundle.sh [--output DIR]` только собирает и подписывает `TenFingers.app` (по умолчанию в `build/`), ничего не устанавливает и не трогает `/Applications`, базу и копии; последней строкой он печатает путь к `.app`. Версия, номер сборки, коммит и поколение схемы (`TFSchemaGeneration`, из `SchemaGeneration.swift` через `scripts/lib-generation.sh`) попадают в `Info.plist`. Подпись ad-hoc, без `--deep`: сначала каждое расширение из `Contents/PlugIns` со своими entitlements, потом приложение, затем `codesign --verify --strict`. Этот же скрипт вызывает `build-app.sh`, а позже — CI при выпуске.
